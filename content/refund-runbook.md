# ขั้นตอนเมื่อลูกค้าขอคืนเงิน

นโยบายที่ประกาศไว้กับลูกค้าอยู่ที่หน้า `/terms` ข้อ 3 และข้อ 4
ไฟล์นี้คือขั้นตอนปฏิบัติของฝั่งเรา

---

## สรุปสั้นๆ ว่าคืนได้ไหม

| สถานการณ์ | คืนไหม | ขอบเขต |
|---|---|---|
| จ่ายแล้วแต่ยังไม่เคยกดดาวน์โหลดเลย | คืนเต็มจำนวน | `full` |
| ดาวน์โหลดไปแล้ว แต่ไฟล์เสีย/เปิดไม่ได้ และเราแก้ให้ไม่ได้ | คืนเต็มจำนวน | `full` |
| ดาวน์โหลดไปแล้ว เปลี่ยนใจเฉยๆ | ไม่คืน | — |
| จ่ายซ้ำ / จ่ายเกิน | คืนส่วนเกินเสมอ | `full` (ของออเดอร์ที่ซ้ำ) |
| นิทาน pre-order ที่ยังไม่ถึงกำหนดส่ง | คืนได้เสมอ ไม่ต้องให้เหตุผล | `preorder` |
| ส่งนิทานล่าช้ากว่ากำหนด | ลูกค้าเลือกได้ว่าจะรอหรือขอคืนเฉพาะเล่มที่ยังไม่ได้ | `preorder` |

เช็กว่าเคยโหลดหรือยังได้จาก `download_events` ของออเดอร์นั้น

---

## ขั้นตอนทำจริง — 3 ขั้น

### ขั้น 1 · ดูสถานะก่อน (ไม่เปลี่ยนอะไร)

```bash
curl -s -X POST https://vinko.quest/api/admin \
  -H "content-type: application/json" \
  -H "x-vinko-admin: $ADMIN_SECRET" \
  -d '{"action":"refund-status","order_ref":"VK-2608-0001"}'
```

จะบอกว่ายอดเท่าไร Omise คืนไปแล้วเท่าไร แต่ละเล่มส่งไปแล้วหรือยัง และคืนไปหรือยัง

### ขั้น 2 · กดคืนเงินจริงที่ Omise

ทำที่ **แดชบอร์ด Omise → Charges → หา charge ของออเดอร์นั้น → Refund**

ระบบเราไม่ได้สั่งคืนเงินให้ เพราะการโยกเงินควรเกิดในที่ที่มีการยืนยันตัวตน
ของเจ้าของอยู่แล้ว ไม่ใช่หลัง endpoint ที่ป้องกันด้วยรหัสเดียว

- คืนเต็มจำนวน → ใส่ยอดเต็ม
- คืนเฉพาะนิทาน pre-order → ใส่เฉพาะส่วนนั้น (ดูตารางแบ่งส่วนในหน้า `/terms` ข้อ 4.4)

### ขั้น 3 · บันทึกฝั่งเราเพื่อตัดสิทธิ์ดาวน์โหลด

```bash
curl -s -X POST https://vinko.quest/api/admin \
  -H "content-type: application/json" \
  -H "x-vinko-admin: $ADMIN_SECRET" \
  -d '{"action":"refund","order_ref":"VK-2608-0001","scope":"full","note":"ลูกค้าขอคืน ยังไม่เคยโหลด"}'
```

`scope` มีสองค่า
- `full` — ตัดสิทธิ์ทั้งออเดอร์ ล้าง token ทิ้ง สถานะเป็น `refunded`
- `preorder` — คืนเฉพาะนิทานที่ยังไม่ได้ส่ง ของที่ส่งไปแล้วลูกค้ายังโหลดได้ตามปกติ

**ขั้นนี้จะไม่ยอมทำงานถ้ายังไม่ได้ทำขั้น 2** เพราะมันไปอ่าน charge จาก Omise
มาตรวจก่อนเสมอว่ามีการคืนเงินเกิดขึ้นจริง ไม่เชื่อสิ่งที่ส่งเข้ามา
ป้องกันกรณี `ADMIN_SECRET` หลุดแล้วมีคนสั่งปิดสิทธิ์ลูกค้าที่จ่ายเงินมาแล้ว

เสร็จแล้วจะมีข้อความเข้า LINE ของเจ้าของเป็นหลักฐานว่าตัดสิทธิ์เมื่อไหร่ ออเดอร์ไหน

---

## หลังทำแล้วเกิดอะไรขึ้นบ้าง

- ลิงก์ดาวน์โหลดเดิมใช้ไม่ได้ทันที (ทั้งกรณี `full` ที่ล้าง token และรายการที่ถูกคืน)
- cron จะไม่ส่งนิทานเล่มที่คืนเงินแล้วให้อีก แม้ถึงกำหนดส่ง
- `orders.refunded_at`, `refund_satang`, `refund_note` เก็บหลักฐานไว้
- ยอดที่บันทึกมาจาก Omise เสมอ ไม่ได้พิมพ์เอง จึงตรงกับที่คืนจริงแน่นอน

---

## สิ่งที่ยังต้องทำเอง

- **แจ้งลูกค้า** ว่าคืนเงินแล้ว และเงินจะเข้าเมื่อไหร่
  บัตรเครดิต 5–15 วันทำการ · PromptPay 3–5 วันทำการ (ตามที่เขียนไว้ในหน้า terms)
- ถ้าลูกค้าจ่ายซ้ำสองออเดอร์ ให้คืนออเดอร์ที่ซ้ำ แล้วทำขั้น 3 กับ `order_ref` ของออเดอร์นั้น
- ยังไม่มีหน้าจอแอดมิน ใช้ curl ตามด้านบน (หรือ Postman) `ADMIN_SECRET` อยู่ใน Vercel
